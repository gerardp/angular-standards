# Templates and styling

Tailwind CSS v4 + Spartan helm components. No CSS preprocessor, no CSS-in-JS, no component library
other than Spartan.

## Tailwind v4 configuration

v4 is **CSS-first**. There is no `tailwind.config.js` — configuration lives in `styles.css`. This
is a durability win: one less JavaScript config file to rot, and the theme is expressed in standard
CSS custom properties.

```css
/* src/styles.css */
@layer theme, base, components, utilities;

@import 'tailwindcss/theme.css' layer(theme);
@import 'tailwindcss/preflight.css' layer(base);
@import 'tailwindcss/utilities.css';

@import '@spartan-ng/brain/hlm-tailwind-preset.css';

@theme {
  /* App-specific design tokens extend the Spartan theme here */
}

:root {
  /* Spartan theme variables — generated by `init` (which invokes the theme generator) */
}
```

**Audit (review):** Flag the creation of a `tailwind.config.js`/`.ts`. In v4 that is a sign someone is
following a v3 tutorial.

## Utilities first, semantic tokens always

Style with Tailwind utilities in the template. Component `styles` are for what utilities genuinely
cannot express.

Use **semantic** classes backed by the theme variables, never raw palette colours:

```html
<!-- Right -->
<div class="bg-card text-card-foreground border-border rounded-lg border p-4">

<!-- Wrong: breaks dark mode, breaks rebranding -->
<div class="rounded-lg border border-gray-200 bg-white p-4 text-slate-900">
```

**Audit (review):** Flag `bg-slate-*`, `text-gray-*`, `border-zinc-*`, hex colours, and `rgb()` outside
`styles.css`.

## When utilities are not enough

Reach for these in order:

1. **A helm variant** — if it is a component-level appearance, it belongs in the CVA config. See
   [spartan-ui.md](spartan-ui.md).
2. **A component in `ui/`** — if the same utility string appears three times, it is a component.
3. **Component `styles`** — for `::ng-deep`-free structural CSS that utilities cannot express:
   complex grid templates, `@container` queries, pseudo-element decoration.

Never a global stylesheet rule targeting a component's internals. Global CSS is the least
maintainable thing in a long-lived app because nothing tells you what depends on it.

**Audit (review):** Flag `::ng-deep` (deprecated and leaky), `!important`, and global selectors in
`styles.css` that target application markup rather than defining tokens or resets.

## Long class lists

Long `class` attributes are fine — that is Tailwind working as intended. Do not extract them into
`@apply` rules to "clean up"; `@apply` recreates the indirection Tailwind exists to remove and
breaks the ability to read a component's appearance from its template.

If a class list is unreadable, the fix is a **component**, not a CSS abstraction.

For conditional classes use bindings, not string concatenation:

```html
<div class="rounded-md p-4" [class.border-destructive]="hasError()">
```

For variant-driven combinations, use the helm component's `variant` input.

## Templates

- Built-in control flow only: `@if`, `@for`, `@switch`, `@let`. Structural directives are banned —
  see [longevity.md](longevity.md).
- `@for` always has `track` with a stable identity.
- `@let` for values used several times in a template, instead of repeating a `computed` call.
- No logic in expressions — see [components.md](components.md#templates).
- Self-closing tags for components with no content: `<app-invoice-row />`.

## Layout

- **Flexbox and Grid only.** No floats, no absolute positioning for layout (only for genuine
  overlays).
- **Logical properties for direction-dependent spacing**: `ms-4`/`me-4`, not `ml-4`/`mr-4`;
  `text-start`, not `text-left`. This costs nothing now and is what makes RTL support a
  configuration change rather than a rewrite. See
  [core-engineering.md](core-engineering.md#internationalisation-readiness).
- **Container queries over viewport breakpoints** for component-level responsiveness. A card should
  respond to the space it is in, not the size of the window. Tailwind v4 has first-class
  `@container` support.
- Mobile-first: unprefixed utilities are the small screen, `md:`/`lg:` widen from there.

**Audit (review):** Flag `ml-*`, `mr-*`, `pl-*`, `pr-*`, `text-left`, `text-right`, `left-*`, `right-*` in
new templates.

## Motion

**Native CSS only.** The `@angular/animations` DSL is deprecated and banned — see
[longevity.md](longevity.md).

For enter/leave animation of elements entering or leaving the DOM, use Angular's `animate.enter`
and `animate.leave` (v20.2+), which apply CSS classes at the right moments and wait for the
animation before removing the element:

```html
@if (isOpen()) {
  <div class="panel" animate.enter="panel-enter">…</div>
}
```

```css
.panel-enter { animation: slide-fade 200ms ease-out; }

@keyframes slide-fade {
  from { opacity: 0; transform: translateY(8px); }
  to   { opacity: 1; transform: translateY(0); }
}
```

For state transitions, toggle a class and let CSS `transition` handle it. For auto-height, use the
`grid-template-rows: 0fr → 1fr` technique rather than measuring in JavaScript.

**Always respect reduced motion:**

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    transition-duration: 0.01ms !important;
  }
}
```

Animate only `transform` and `opacity` where possible — they are the properties the compositor can
handle without layout or paint.

**Audit (partial):** Flag any import from `@angular/animations`. Flag animations of `width`, `height`, `top`,
or `left` where `transform` would work. Flag a codebase with no `prefers-reduced-motion` handling.
*Lint covers:* the `@angular/animations` import — it is in the global banned-package list.
*You check:* which properties are animated, and whether `prefers-reduced-motion` is handled anywhere.
Both live in CSS, which ESLint does not read.

## Images and assets

- Use `NgOptimizedImage` (`ngSrc`) for content images — it enforces sizing, lazy-loads, and
  generates responsive `srcset`.
- Mark the largest above-the-fold image `priority`.
- Always set `width` and `height` (or `fill` with a sized container) so the layout does not shift.
- SVG icons inline or as components, never an icon font.

**Audit (review):** Flag `<img src>` for content images where `ngSrc` should be used, and any `<img>`
without dimensions.
